# 流(Stream)

首先我们不使用流来玩玩 正常读取文件并返回有哪些问题呢?
- 当需要返回内容过大
- 需要读取的文件内容过多
```shell
curl -i http://localhost:8000

HTTP/1.1 200 OK
Date: Fri, 16 Oct 2026 01:49:45 GMT
Connection: keep-alive
Keep-Alive: timeout=5
# 响应体长度(当数据量小这样 服务器这样返回是完全没有问题的, 遇到大文件则会出现问题)
Content-Length: 11

Hello World
```


大文件使用流和直接读取区别

```shell
# 直接读取
curl -i http://localhost:8000
HTTP/1.1 200 OK
Date: Fri, 16 Oct 2026 02:16:14 GMT
Connection: keep-alive
Keep-Alive: timeout=5
Content-Length: 7572224

// 流读取
curl -i http://localhost:8001
HTTP/1.1 200 OK
content-type: image/jpeg
Date: Fri, 16 Oct 2026 02:16:16 GMT
Connection: keep-alive
Keep-Alive: timeout=5
# 因为流形式返回 所以 并不知道响应体有多长 所以 通过 Transfer-Encoding 字段方式 标识流返回
Transfer-Encoding: chunked
```

那么从服务器下载一个文件 怎么直到文件是否下载完了呢?
这里有两种方式 
- 一个是 Header 带上 Content-Length, 浏览器下载到指定长度久表示结束
- 一个是流返回 通过 `Transfer-Encoding: chunked` 标识, 服务器会不断返回内容 直到返回一个空表示结束

大文件流式传输原理就是设置 `transfer-encoding: chunked`

流是什么?
- 流就是 一段段读取 目标的内容在给予结果, 比如服务端像浏览器返回响应数据流, 读取文件流等信息
- 流之间可以通过 pipe 连接, 像水管一样 不断连接在一起, 流通上个水管的水接着下个水管继续流

## 流分类
1. 流分为: 其他的流都是基于以下这些 基类 进行封装
- 可读流: Readable
- 可写流: Writable
- 双工流: Duplex
- 转换流: Transform
