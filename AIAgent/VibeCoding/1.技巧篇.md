# 技巧篇
> https://code.claude.com/docs/zh-CN/sub-agents#quickstart-create-your-first-subagent

**无论 Agent 演进多么复杂它的最终目的都是为了更好的生成一个 传给 LLM 的 Prompt 后得到一个结果**

## ClaudeCode 的特点
拥有 Command/Agent/Hooks/Skills 等自动化功能
Skills 就是为了弥补 MCP 的缺点: 占用的 Token 太多
根据 Claude.md 来管理 项目上下文, 它采用 **递归读取机制** 从当前目录向上查找所有 CLAUDE.md 文件 我们需要 节制的使用
### 项目上下文管理
1. 全局配置最佳实践
```md
# 我的全局编码偏好

## 通用规范
- 使用 TypeScript 而非 JavaScript
- 函数不超过 50 行
- 测试覆盖率 > 80%

## 提交规范
遵循 Conventional Commits:
- feat: 新功能
- fix: Bug 修复
- docs: 文档更新
- refactor: 重构

## 我的工作流
- 功能分支：`feature/[issue-id]-description`
- 永远 rebase，不要 merge
- Push 前必须通过 lint 和 test
```
2. 项目根目录:
```md
# 项目: E-Commerce Platform

## 技术栈
- Frontend: Next.js 14 + React 18 + TailwindCSS
- Backend: Node.js + Express + PostgreSQL
- Deploy: Vercel (frontend) + AWS Lambda (backend)

## 核心文件
- `@src/lib/db.ts` - 数据库连接和查询工具
- `@src/lib/auth.ts` - JWT 认证逻辑
- `@docs/API.md` - API 文档

## 禁止修改
- `src/lib/legacy/` - 遗留代码，正在迁移中
- `prisma/migrations/` - 数据库迁移历史
- `.github/workflows/` - CI/CD 流水线（DevOps 团队管理）

## 代码组织
按功能模块组织，而非文件类型：
src/ features/ auth/

AuthService.ts
AuthController.ts
auth.test.ts products/
ProductService.ts
ProductController.ts
products.test.ts

## 命名约定
- React 组件: PascalCase (UserProfile.tsx)
- 工具函数: camelCase (getUserData.ts)
- 常量: UPPER_SNAKE_CASE (MAX_RETRY_COUNT)
```
3. 特性子模块
```md
# 支付模块

## Stripe 集成
使用 Stripe Checkout 和 Webhooks。
关键文件：
- `StripeService.ts` - Stripe SDK 封装
- `webhooks.ts` - Webhook 处理器

## 测试要求
```

### Hook
Hooks 允许在特定生命周期上 调用 Shell 命令
```json
// ~/.claude/config.json
{
  "hooks": {
    "onToolCall": {
      "Edit": "echo '文件被修改' >> changelog.txt"
    },
    "onUserSubmit": "npm run lint",
    "onSessionStart": "git fetch origin",
    "onBeforeCommit": "npm test"
  }
}
```
